# RMM — Deployment and Operational Setup

---

## 1. Hosting

**Provider:** Vercel  
**Plan:** Hobby (confirmed from OIDC token payload in `.vercel` config)  
**Project name:** `runmadmaps`  
**Project ID:** `prj_fCm1AlDGiKPRrrWxXC5adzc9oTka`  
**Org/team ID:** `team_p3HQlIUmpSLtOAnZMGVhqfIF`

The site is a zero-config static deployment on Vercel. There is no build step, no bundler, and no output directory. Vercel serves the project root directly. Serverless functions in the `/api/` directory are auto-detected and deployed as Vercel Functions.

**Hobby plan implications:**
- Serverless function execution time limit: 10 seconds (Hobby) vs 15 seconds (Pro)
- **Maximum 12 serverless functions per deployment** — this is a hard limit on Hobby. The project currently uses all 12 slots (4 auth + 2 Node API + 6 Python). Any new endpoint requires combining existing ones or upgrading to Pro.
- No team collaboration features
- Vercel SLAs do not apply
- Function invocations and bandwidth are subject to Hobby tier limits

## 2. Build Process

There is no build process. This is intentional — the project uses no bundler, no transpiler, no framework, and no npm dependencies.

**`package.json`** exists solely for project metadata:

```json
{
  "name": "runmadmaps",
  "version": "0.1.0",
  "description": "Run Mad Maps — Trail intelligence for the Cape Peninsula",
  "private": true,
  "author": "Valken de Villiers",
  "license": "UNLICENSED"
}
```

No `scripts`, no `dependencies`, no `devDependencies`.

**What Vercel does on deploy:**
1. Detects no framework (no `next.config.js`, no `vite.config.js`, etc.)
2. Treats the project as a static site
3. Deploys the project root as-is
4. Auto-deploys `/api/*.js` files as serverless functions
5. Applies `vercel.json` rewrites and headers
6. No build command runs. No output directory is specified.

**Local development:** There is no `npm run dev` or `npm start` command. Local development is done via Vercel CLI (`vercel dev`), which is confirmed by the presence of `.env.local` (a file created by `vercel dev` when it pulls env vars from the Vercel dashboard). Without `vercel dev`, local API functions do not work — but HTML/CSS/JS files can be opened directly in a browser.

## 3. Environment Variables

All secrets are stored in Vercel environment variables (set via the Vercel dashboard or Vercel CLI). Locally, they live in `.env.local` (generated by `vercel dev`, gitignored). Never in code, never in comments.

### Production Variables (7 core + 2 Strava + 93 formula = 102 total)

| Variable | Used By | Purpose |
|---|---|---|
| `MAPBOX_PUBLIC_TOKEN` | `api/config.js` → client | Mapbox GL JS access token. Delivered to the client via `/api/config`. Public token (safe to expose, but delivered server-side to avoid it appearing in source). |
| `MAPBOX_STYLE_URL` | `api/config.js` → client | Mapbox Studio style URL (`mapbox://styles/...`). Identifies which custom style the map loads. |
| `TRAILS_TILESET_ID` | `api/config.js` → client | Mapbox tileset ID for the custom trail network layer. Optional — if absent, trail lines do not render. |
| `CONTOURS_TILESET_ID` | `api/config.js` → client | Mapbox tileset ID for the elevation contour layer. Optional — if absent, contours do not render. |
| `SUPABASE_URL` | `api/config.js` (style_config read) + `api/subscribe.js` | Supabase project REST API URL (`https://[project-ref].supabase.co`). |
| `SUPABASE_ANON_KEY` | `api/config.js` (style_config read) + hardcoded in `scripts/map.js` | Supabase anon/public key. Safe to expose client-side by design (Supabase Row Level Security enforces access). Also hardcoded directly in `map.js` for the client-side `style_config` fetch — meaning this key is visible in the browser. |
| `SUPABASE_SERVICE_ROLE_KEY` | `api/subscribe.js` only | Supabase service role key. Bypasses RLS — full database access. Server-side only. Never delivered to the client. |

### Strava OAuth Variables (2 required, added 2026-05-03)

| Variable | Used By | Purpose |
|---|---|---|
| `strava_oauth_client_id` | `api/auth/strava-login.js`, `strava-callback.js`, `session.js` | Strava app client ID (163342) |
| `strava_oauth_client_secret` | `api/auth/strava-callback.js`, `session.js` | Strava app secret — server-only |

### Formula Variables (93 total — added 2026-04-25 to 2026-05-05)

All formula engine thresholds, weights, and ceilings. Read by `api/python/config.py` via `os.environ`. Same names as Formula Lab `.env`. Full list with values in `vercel-paste-ready.txt`.

**Currently set in Vercel:** 60 (route grading only — Distance Bands, ED Bands, Base Class Matrix, Grade Modifiers, TDS, Effort, Climb, Pillar 3, TBS/RCS Weights, Gradient, Moving Time, DEM, Pace Consistency).

**Prepared but NOT YET set:** 33 additional vars for RPS, Race Readiness, Anti-Gaming (RPS Weights, Ceilings per discipline, Decay, Levels, PI Expected Paces, RR Thresholds, AG Thresholds, PC Gradient, TDS Bonus). These are in `vercel-paste-ready.txt` ready to paste into the Vercel bulk editor.

**Helper files:**
- `vercel-paste-ready.txt` — all 93 vars with values, Vercel bulk-paste format (KEY=VALUE)
- `set-env-vars.ps1` — PowerShell script that pipes values into `vercel env add` CLI (only has route grading subset)
- `vercel-env-template.txt` — blank template with comments for documentation

### Known Local Env Issue

`.env.local` (Vercel CLI-generated) contains a duplicated prefix in `MAPBOX_STYLE_URL`:

```
MAPBOX_STYLE_URL="MAPBOX_STYLE_URL=mapbox://styles/..."
```

The value includes the variable name as a prefix, making the actual value `MAPBOX_STYLE_URL=mapbox://...` instead of `mapbox://...`. This would cause the map to fail locally with a "style not found" error. The Vercel dashboard likely has the correct value — this is a local-only artifact of how the CLI wrote the file. Fix: edit `.env.local` to remove the prefix from the value.

## 4. Domains

**Production domain:** `runmadmaps.com`  
**Vercel default URL:** `runmadmaps.vercel.app` (standard Vercel project subdomain)

DNS configuration is not visible from the codebase. Domain is referenced throughout:

- OG/Twitter meta tags in `pages/map.html` (`https://runmadmaps.com`)
- CORS allowlist in `api/config.js`: `['https://runmadmaps.com', 'http://localhost:3000']`
- CORS allowlist in `api/subscribe.js`: `'https://runmadmaps.com'` only (no localhost — subscribe API does not work in local dev without modifying this)
- All canonical URLs in HTML meta tags

**Note on localhost in subscribe.js:** The subscribe endpoint does not include `localhost` in its CORS `Access-Control-Allow-Origin`. This means email capture form submissions will fail locally with a CORS error unless the header is temporarily relaxed during development.

## 5. Git Workflow

**Repository:** `https://github.com/ValkenMadness/runmadmaps.git`  
**Branching:** `main` is both the working and production branch. All work pushes directly to `main`. Feature branches are optional for large isolated features or risky refactors.  

**Deployment trigger:** Push to `main` → Vercel auto-deploys to production. Every commit to `main` goes live immediately. This is intentional — all experimental/incomplete features are gated behind admin access (`localStorage.rmm_admin`), so the public only sees finished work.

**Previous workflow (deprecated 2026-05-12):** A `dev` → `main` squash-merge workflow was documented but never consistently used. Removed in favour of direct-to-main deploys since admin gating makes preview URLs unnecessary for most changes.

## 6. Monitoring

**Error tracking:** None. No Sentry, no Datadog, no Rollbar, no Vercel Error Tracking configured.

**Analytics:** None. No Google Analytics, no Plausible, no Fathom, no Vercel Analytics script in any HTML page.

**Logging:** 
- `api/config.js`: no logging
- `api/subscribe.js`: `console.error` on Supabase failure and caught exceptions — logs appear in Vercel function logs
- `scripts/map.js`: `console.log` for icon load confirmations, `console.error` for icon failures, route load, Supabase errors — browser console only, not captured anywhere

**Vercel dashboard:** Provides basic function invocation logs, edge network metrics, and deployment history. This is the only operational visibility available.

**What this means in practice:** There is no alerting. If the map breaks, the subscribe API fails, or Supabase goes down, nothing notifies anyone. Discovery is manual.

6. Deployment takes ~30–60 seconds
7. Vercel supports instant rollback to any previous deployment via the dashboard

## 8. Security

### Security Headers (via `vercel.json`)

Applied globally to all routes (`/(.*)`):

| Header | Value | What It Does |
|---|---|---|
| `X-Content-Type-Options` | `nosniff` | Prevents browsers from MIME-sniffing responses away from their declared content type |
| `X-Frame-Options` | `DENY` | Prevents the site from being embedded in any iframe (clickjacking protection) |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Sends full URL as referrer for same-origin requests; only origin for cross-origin |

### Missing Security Headers

| Header | Status | Risk |
|---|---|---|
| `Content-Security-Policy` | Not set | No CSP means no protection against XSS injection into map popups or overlay HTML. The map popup uses `setHTML()` with data from GeoJSON files (controlled input, low risk currently). The email overlay uses string concatenation for HTML. |
| `Strict-Transport-Security` | Not set | Vercel adds HTTPS at the edge, but no HSTS header to enforce it |
| `Permissions-Policy` | Not set | No restriction on browser feature access (camera, microphone, geolocation, etc.) |
| `X-XSS-Protection` | Not set | Deprecated in modern browsers, but legacy browsers unprotected |

### CORS Configuration

`api/config.js` (GET — token delivery):
```
Allowed origins: https://runmadmaps.com, http://localhost:3000
Method: GET only
```

`api/subscribe.js` (POST — email capture):
```
Allowed origins: https://runmadmaps.com only (no localhost)
Methods: POST, OPTIONS
```

### Rate Limiting

None. There is no rate limiting on either API endpoint. The subscribe endpoint is protected only by Supabase's unique email constraint (returns 409 on duplicate). A bot could spam the `/api/subscribe` endpoint without restriction, consuming Supabase write quota and Vercel function invocations.

### Secret Management

- All secrets in Vercel environment variables — not in code ✅
- `.gitignore` excludes `.env`, `.env.local`, `.env.production` ✅
- `SUPABASE_SERVICE_ROLE_KEY` server-side only ✅
- `SUPABASE_ANON_KEY` intentionally client-accessible (Supabase publishable key) — hardcoded in `scripts/map.js` and also stored as env var ✅
- No tokens, API keys, or credentials in git history (verified by absence from committed files) ✅

### Input Validation

`api/subscribe.js`:
- Name: trimmed, required
- Email: trimmed, lowercased, regex validated
- Source: sanitized to `[a-zA-Z0-9_\-]`, max 64 chars, defaults to `'landing_page'`

`api/config.js`:
- No user input accepted — GET only, returns env vars

Client-side (`scripts/map.js`):
- Email overlay validates name, email format, and consent checkbox before submitting
- Validation is duplicated client-side and server-side (correct pattern)

## 9. External Service Dependencies

| Service | What Breaks If Unavailable |
|---|---|
| Vercel | Everything |
| GitHub | Deployments (push → deploy trigger); codebase access |
| Mapbox CDN (`api.mapbox.com`) | Map does not load (GL JS and CSS served from CDN) |
| Mapbox Tiles API | Map style, 3D terrain, satellite imagery do not render |
| Supabase | Subscribe API fails; `style_config` overrides not applied (map falls back to defaults gracefully) |
| Google Fonts CDN | Space Mono does not load; browser falls back to system monospace |

All Mapbox CDN resources are loaded from `https://api.mapbox.com/mapbox-gl-js/v3.3.0/`. The version is pinned — no automatic updates. If Mapbox deprecates v3.3.0, a manual update is required.
